# CyberSathi — Master Build Prompt for VS Code AI Extensions

> **How to use this file**
> 1. Open an empty folder in VS Code (e.g. `cybersathi/`).
> 2. Open a free agentic coding extension: **Cline**, **Roo Code**, **Continue**, **Kilo Code**, or **GitHub Copilot (Agent mode)**.
> 3. Paste **PROMPT 0** first. Then paste **PROMPT 1 … PROMPT 9** one at a time, waiting for each to finish.
> 4. If your extension has a small context window, paste only the phase prompt plus the Global Contract.
> 5. Free model options: Ollama (`qwen2.5-coder:7b`, `deepseek-coder-v2`), Groq free tier, Google AI Studio (Gemini free tier), OpenRouter free models.

# PROMPT 2 — Datasets and ML training pipeline

```
PHASE 2 - Generate the datasets and train both models. All data must be SYNTHETIC or
paraphrased public-awareness examples. Defang every URL in stored data (hxxp://, [.]).

A) backend/data/scam_messages.csv - columns: text, language, label, category, source
   - >= 600 rows: about 320 scam and 280 legitimate. About 40% Tamil in real Tamil script
     (not transliteration only); also include 60+ Tanglish rows, since rural users type that way.
   - Categories: otp, kyc, job, investment, banking, loan, impersonation, social_media,
     lottery, courier_parcel, electricity_bill, digital_arrest, legitimate.
   - Scam rows should realistically contain: urgency ("immediately", "உடனே"), account-block
     threats, shortened links, "share OTP", "pay processing fee", "KYC expired", fake bank
     sender ids, guaranteed-return promises, WhatsApp-only contact, grammar anomalies.
   - Legitimate rows: real-style OTP notices that say "do not share", delivery updates,
     bank balance alerts, exam results, genuine interview call letters.

B) backend/data/urls.csv - columns: url, label, source
   - >= 800 rows, balanced. Phishing-style rows imitate patterns only (typosquats such as
     "sbi-kyc-update-verify[.]xyz", IP-host URLs, "@" tricks, punycode, deep subdomains,
     free TLDs, long query strings). Never use a real live malicious domain.

C) backend/app/ml/features.py
   URL features (>= 22, all static, no network calls): url_length, hostname_length, path_depth,
   num_dots, num_hyphens, num_digits, digit_ratio, has_ip_host, has_at_symbol, num_subdomains,
   is_https, port_present, suspicious_tld (tk/ml/ga/cf/gq/xyz/top/buzz/click/zip/mov),
   shortener_flag (bit.ly/tinyurl/t.co/rb.gy/cutt.ly), brand_keyword_hit
   (sbi, hdfc, icici, paytm, phonepe, gpay, upi, netflix, amazon, irctc, epfo, income-tax),
   sensitive_word_hit (login, verify, kyc, update, secure, account, otp, wallet, refund),
   entropy_of_host, has_punycode, hyphen_in_domain, double_slash_in_path,
   query_param_count, is_typosquat_levenshtein (<=2 from the brand list), tld_length.
   Text features: TF-IDF word 1-2 grams (max_features=20000, sublinear_tf, min_df=2)
   unioned with char_wb 3-5 grams, plus numeric side-features (has_link, has_phone,
   has_amount, urgency_count, threat_count, reward_count, imperative_count, all_caps_ratio).

D) backend/app/ml/rules.py - a bilingual regex rule engine. Each rule is
   {id, pattern_en, pattern_ta, weight 0-1, category, explanation_en, explanation_ta}.
   At least 30 rules covering: OTP sharing, fee-before-job, KYC link, lottery win,
   digital arrest, investment doubling, loan pre-approval, SIM block, electricity
   disconnection, customs parcel, matrimonial/romance, sextortion threat, fake police/CBI,
   APK file link, "screen share / AnyDesk / TeamViewer", and "UPI request to RECEIVE money".

E) backend/app/ml/redaction.py - mask 6-digit OTPs, 12/16-digit numbers, Aadhaar pattern,
   PAN, IFSC, phone numbers, emails and UPI VPAs to "[REDACTED_OTP]" style placeholders.
   Returns (redacted_text, found_types[]). Call it before any DB write or log line.

F) ml_training/train_text_model.py and ml_training/train_url_model.py
   - Stratified 80/20 split, Pipeline + GridSearchCV (small grid), 5-fold CV,
     class_weight='balanced', calibrated probabilities.
   - Save to app/ml/artifacts/text_model.joblib and url_model.joblib, plus metadata.json
     (trained_at, rows, classes, metrics, sklearn version).
   - Targets: text macro-F1 >= 0.90, URL accuracy >= 0.92. If below, print a tuning report.
   - Explainability: expose the top-N contributing tokens (LogReg coefficients) and the
     top URL features (feature_importances_ plus per-sample rule hits).

G) ml_training/evaluate.py - write docs/ML_METRICS.md with a metrics table and confusion
   matrices saved as PNGs under docs/img/.

Run both trainers and paste the real metrics.
```

# PROMPT 3 — Module 1 & 2: Scam Analyzer + Phishing URL Checker

```
PHASE 3 - Detection services and endpoints.

POST /api/v1/scam/analyze
  body: {text: str(1..5000), channel: sms|whatsapp|email|call_transcript, language?: auto|en|ta}
  pipeline: detect language -> redact PII -> rule engine -> ML classify ->
            hybrid score = 0.55 * ml_prob + 0.45 * normalised_rule_weight
  response: {
    risk_score: 0-100, risk_label: safe|suspicious|high_risk,
    primary_category, categories: [{name, confidence}],
    language_detected,
    signals: [{rule_id, matched_snippet_redacted, why_en, why_ta, weight}],
    top_terms: [{term, contribution}],
    explanation: {en, ta},              # 3-5 short sentences, 8th-grade reading level
    safe_actions: {en: [...], ta: [...]},  # do not click, call 1930, verify in the official app
    related_kb_slugs: [...],
    helplines: {cyber_crime: "1930", portal: "cybercrime.gov.in", bank: "use the number on your card"},
    disclaimer: {en, ta}, analysis_id
  }
  Thresholds: <35 safe, 35-69 suspicious, >=70 high_risk. Persist ScamAnalysis (redacted text only).

POST /api/v1/url/check
  body: {url: str} - validate, but ACCEPT defanged input; auto-undefang hxxp and [.] for
  analysis and NEVER request the URL.
  response: {risk_score, risk_label, features: {...},
             top_reasons: [{feature, value, why_en, why_ta}],
             lookalike_brand?: "SBI", advice: {en, ta}, disclaimer, check_id}
  Also add POST /api/v1/url/bulk-check (max 20 URLs, returns an array) for workshop demos.

GET /api/v1/scam/examples?category=&language= - curated safe demo samples so facilitators can
  demo without typing real scam texts. Seed at least 24 examples.

Rate-limit the public detection endpoints (in-memory token bucket, 30 requests/minute/IP).

Tests: high-risk OTP scam -> high_risk; legitimate bank alert -> safe; a Tamil scam text ->
high_risk with a Tamil explanation; an IP-host URL -> high_risk; https://www.google.com -> safe;
and PII present in the input never appears in the stored row.
```

# PROMPT 5 — Module 5: Multilingual AI Assistant

```
PHASE 5 - Bilingual assistant with a deterministic fallback.

POST /api/v1/assistant/ask
  body: {question: str, language: auto|en|ta, session_id?: str, simple_mode?: bool}
  Answer resolution order:
   1. SAFETY GATE: refuse requests to write or generate scam/phishing content, or to
      "hack / trace / recover" money illegally. Return an awareness answer plus the helpline.
   2. INTENT layer: if the question contains a pasted message or URL, auto-route it to the
      scam or URL analyzer and return that verdict conversationally.
   3. KB RETRIEVAL: TF-IDF cosine similarity over article title + summary + body in the
      detected language. If the best score is >= 0.25, compose the answer from that article
      (summary + 3 red flags + 3 safe actions + link), source = "kb".
   4. OPTIONAL LLM: if ENABLE_LLM=true and Ollama is reachable, send a strictly grounded
      prompt (system: "Answer ONLY from the provided context; reply in {language}; max 120
      words; simple words; if the context is insufficient say you do not know and give
      helpline 1930."). Timeout 20s, source = "llm". On any failure fall back silently.
   5. FALLBACK: a friendly bilingual "I am not sure" plus the top 3 related articles and 1930.
  response: {answer, language, source, confidence, related_articles[], suggested_questions[3],
             disclaimer, log_id}

POST /api/v1/assistant/feedback {log_id, helpful: bool, comment?}
GET  /api/v1/assistant/suggestions?language= - 10 starter questions per language.

Also implement the "Explain like I am 60" mode: when simple_mode=true, answers use sentences
under 12 words and avoid all technical terms (say "fake message", not "phishing").

Tests: a Tamil question returns a Tamil answer; a scam-generation request is refused with an
awareness reply; the LLM-disabled path still returns a useful KB answer; an unknown topic
falls through to the fallback.
```

# PROMPT 6 — Module 6 & 7: Assessment engine + Impact dashboard

```

   GET  /api/v1/assessment/questions?type=pre|post&language=&count=10

   POST /api/v1/assessment/submit
```

## The impact formula as implemented

```
improvement_percentage = ((post_score - pre_score) / pre_score) * 100
```

With one honesty guard: when `pre_score == 0` the percentage is undefined (division by zero),
so the app reports **absolute gain** and **normalized gain** `(post - pre) / (max - pre)`
instead. Both appear in the UI and in the exported report.

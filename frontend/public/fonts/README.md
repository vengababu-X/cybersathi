# Self-hosted fonts

These files are generated by `frontend/scripts/fetch-fonts.py`. Do not edit them by hand.

| File | What it is |
|---|---|
| `fonts.css` | `@font-face` rules pointing at the local `.woff2` files, with the original `unicode-range` values preserved so a browser still only downloads the subset it needs |
| `inter-*.woff2` | Inter, weights 400 / 500 / 600 / 700, `latin` and `latin-ext` subsets |
| `noto-sans-tamil-*.woff2` | Noto Sans Tamil, weights 400 / 500 / 600 / 700, `tamil`, `latin` and `latin-ext` subsets |

## Why they are bundled

Loading fonts from a CDN means that offline — which is the normal condition in a village
hall — Tamil falls back to whatever the device happens to have installed, or to nothing at
all. Bundling makes the typography part of the offline build instead of a dependency on
Google being reachable at the moment a workshop runs.

Only the `latin`, `latin-ext` and `tamil` subsets are shipped. Cyrillic, Greek, Vietnamese
and the other subsets Google serves are dead weight for an English + Tamil application.
